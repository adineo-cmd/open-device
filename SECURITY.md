# Security policy

## What this project does and does not do

Open Device documents what proprietary firmware *is*. It does **not** hunt for
vulnerabilities: CVE hunting and classical-cipher cryptanalysis are explicitly
excluded by the lab owner in `SCOPE.md`. Do not open issues asking us to find or
publish an exploit; they will be closed.

If your security work touches this repository's infrastructure rather than the
firmware being studied, read on.

## Reporting a repository-security issue

Report privately via GitHub's "Report a vulnerability" for this repository, or
by contacting the owner privately. Please include:

- affected file or workflow,
- impact and a minimal reproduction,
- whether you believe any proprietary payload is at risk of being committed.

Do **not** open a public issue for: leaked firmware, device-private data, or a
vulnerability in a vendor firmware image. We cannot accept those uploads — the
no-blobs boundary in `SCOPE.md` applies to reports too.

## Supported material

Only the current tip of `feat/open-device-site` and the published GitHub Pages
site are maintained. Research findings are historical records; they are not
patched for security issues.

## Hardening already in place

- `.gitignore` blocks firmware and binary payload extensions; component-level
  `fixtures/.gitignore` files cover `.fw`/`.tlv`.
- All implementation fixtures are synthetic and generated by committed
  `make_fixture.py` scripts.
- CI (`.github/workflows/tests.yml`) runs all self-tests and repository checks
  on every push and pull request.
- No secrets or credentials are stored in the repository.
